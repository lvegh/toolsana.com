# Deploying the API on CloudPanel (nginx + PM2)

Origin topology: Cloudflare Pages (frontend) → Cloudflare Worker → **this API**,
running under PM2 on a VM managed by CloudPanel, with nginx as the reverse proxy.

The steps below close M9 (origin lockdown) at the network layer. The application
layer half — `EDGE_SECRET` / `X-Edge-Auth` — is already in the code.

---

## 1. Bind the app to loopback (the important one)

`HOST=0.0.0.0` publishes the API on the VM's public IP. Anyone who learns the IP
can reach `http://<vm-ip>:3010/api/...` directly, bypassing nginx, Cloudflare and
the Worker — which is exactly the bypass the edge secret exists to catch.

nginx proxies from the same host, so loopback is all it needs:

```bash
# toolzyhub-api/.env on the VM
HOST=127.0.0.1
```

> Docker local development needs `0.0.0.0` (the host port mapping cannot reach a
> loopback-bound listener inside the container). This is a **production-only**
> value — do not change the committed local `.env`.

After this, the firewall rules below are defence in depth rather than the only
thing standing between the internet and the API.

## 2. Resolve the port discrepancy

`.env` says `PORT=3001`; `ecosystem.config.js` says `3010`. PM2 sets its value in
the process environment and `dotenv` does not override existing variables, so
**production listens on 3010** (verified: the API binds 0.0.0.0:3010; 3001 on the same VM is an unrelated websocket service). Set `PORT=3010` in `.env` so both agree. Make them agree before writing firewall rules
against the wrong port.

## 3. Restrict nginx to Cloudflare

In the CloudPanel vhost (Sites → your site → Vhost), inside the `server` block:

```nginx
# Only Cloudflare may reach this origin.
# Ranges: https://www.cloudflare.com/ips-v4 and /ips-v6 — re-check quarterly.
include /etc/nginx/cloudflare-ips.conf;   # generated by the script below
deny all;
```

Generate and refresh the list:

```bash
{
  for ip in $(curl -s https://www.cloudflare.com/ips-v4); do echo "allow $ip;"; done
  for ip in $(curl -s https://www.cloudflare.com/ips-v6); do echo "allow $ip;"; done
} > /etc/nginx/cloudflare-ips.conf
nginx -t && systemctl reload nginx
```

## 4. Restore the real client IP

Without this, every request appears to come from a Cloudflare edge address, and
rate limiting and IP bans become global rather than per-client:

```nginx
set_real_ip_from 103.21.244.0/22;   # ...all Cloudflare ranges
real_ip_header CF-Connecting-IP;
```

The API reads `CF-Connecting-IP` itself (see `middleware/edgeProxy.js`), so this
mainly fixes nginx's own logs and the `req.ip` fallback path.

## 5. Firewall

```bash
ufw allow 22/tcp
ufw allow 443/tcp
ufw deny 3010/tcp     # belt and braces; step 1 already prevents external access
ufw enable
```

If your VM provider also offers a network firewall, mirror it there — that layer
survives a misconfigured ufw.

## 6. Secrets

```bash
# On the VM, in toolzyhub-api/.env
EDGE_SECRET=<value>          # uncomment the generated one
DISABLE_API_AUTH=false
NODE_ENV=production

# On Cloudflare — must be the SAME value
npx wrangler secret put EDGE_SECRET
```

The API refuses to start in production if `EDGE_SECRET` is missing, unless
`ALLOW_DIRECT_ORIGIN=true` is set deliberately (see
`../MIGRATION-OFF-CLOUDFLARE.md`).

## 7. Delete the stale DigitalOcean config

`toolzyhub-api/app.yaml` describes a DigitalOcean App Platform deployment that
does not exist. It sets a different `PORT` (8080) and its own `NODE_ENV`, so it
is actively misleading when debugging. Remove it.

---

## 8. System packages

The PNG compression endpoint (`POST /api/compress/png`) shells out to two
system binaries instead of the `imagemin-pngquant` / `imagemin-optipng`
wrappers, which downloaded (or compiled) the exact same binaries at
`npm install` time. Install them once per VM:

```bash
sudo apt update
sudo apt install -y pngquant optipng
```

Verify:

```bash
pngquant --version   # 2.17.x or newer
optipng -version | head -1
```

The API logs a warning at startup if either is missing
(`PNG compression will fall back to Sharp — install with: apt install pngquant optipng`)
but keeps running, so a missing package degrades the endpoint instead of taking
the service down.

If the binaries are not on `PATH` (custom build, non-standard prefix), point the
API at them explicitly in the environment:

```bash
PNGQUANT_PATH=/usr/local/bin/pngquant
OPTIPNG_PATH=/usr/local/bin/optipng
```

## Verifying

From a machine that is not Cloudflare:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://<vm-ip>:3010/api/dns/info   # expect: connection refused
curl -sS -o /dev/null -w '%{http_code}\n' https://api.toolzyhub.app/api/dns/info  # expect: 403 (EDGE_REQUIRED)
curl -sS -o /dev/null -w '%{http_code}\n' https://api-worker.toolzyhub.app/api/dns-info  # expect: 200
```

The middle one returning 403 is the whole point: reachable through Cloudflare,
rejected without the Worker's header.
